# シャッフルランチ 仕様書

## 1. 目的
入社半年以内の社員が、配属先以外の部署に「気軽に話せる人」を作れるようにする。
特に、同期のいない中途入社の人と、人と知り合う機会の少ないリモート勤務の人を支える。

### 成功の基準
1. 入社3ヶ月の時点で、配属先以外に「気軽に話せる人」が3人以上いる
2. リモート勤務の人の参加率が、出社中心の人と同じくらいある

## 2. 使う人
| 立場 | 説明 |
|---|---|
| 新入社員 | 入社半年以内（新卒・中途）。入社日から自動で判定 |
| 迎える側 | 既存の社員。手を挙げた人が登録する。参加回数の上限なし |
| 運営 | 人事など。開催の設定と集計を見る |

- 入社半年を過ぎた新入社員は、自動で「迎える側」に切り替わる。続けるかは本人が選ぶ（切り替え時にメールで案内）
- 出社の人とリモートの人が混在している

## 3. 決まったこと（概要）
| 項目 | 決定 |
|---|---|
| 頻度 | 2週間に1回（1回＝2週間の開催期間） |
| 人数 | 1グループ3〜4人 |
| 組み合わせ | 新入社員と迎える側の混合。全員が別の部署 |
| 形式 | 毎回、本人が「対面」か「オンライン」を選ぶ。同じ形式の人どうしで組む |
| 日程 | 申込時に開催期間内の都合のよい日を複数選び、全員が空いている日で組む |
| 申込 | 一度登録すれば毎回自動で対象。各回は「候補日を選ぶ」か「今回は休む」だけ |
| ランチ代 | 会社が補助。オンラインも同額。アプリは参加記録だけを持ち、精算は既存の経費システムで行う |
| お知らせ | メール＋カレンダー招待（オンラインは Google Meet の URL を自動で付ける） |
| ログイン | Google Workspace のアカウント |
| 社員情報 | 本人が初回ログイン時に入力 |
| 運営の確認 | なし。締切後に自動で組み、そのまま通知する |

## 4. 作る範囲
5章以降は完成したときの仕様。最初の版はその一部だけを作り、残りは「あとで足すもの」として順に足す。

### 最初に作るもの
| 機能 | 内容 |
|---|---|
| ログイン | Google Workspace のアカウントでログイン（初回登録の前提として含める） |
| 初回登録 | 部署（一覧から選ぶ）、入社日、勤務形態、迎える側として参加するか、を入力（8章「初回登録」） |
| ホーム | 今回の回をカレンダーで表示し、回答の状態を出す。「候補日を選ぶ」「今回は休む」 |
| 回答 | 形式を選ぶ → 候補日をカレンダーで選ぶ → 完了、の順に進む。締切までは何度でも直せる（8章） |
| 組み合わせ | 運営がボタンを押して実行する（下記） |
| ランチの詳細 | メンバーの名前・部署、日時、形式 |

**組み合わせ（最初の版）**
- 自動では実行しない。運営画面の「組み合わせを実行」ボタンで実行する
- 実行できるのは1回につき1度だけ。実行するとその回の回答は締め切られる
- 結果はすぐホームとランチの詳細に表示される（メールは送らない）。組めなかった人にはホームで「今回は見送り、次回優先」と表示する
- ルールは6章のとおり。ただし「組みたくない人」は登録画面がないため、最初の版では使わない

**運営画面（最初の版）**
- 回を作る：開催期間と締切日を入力する。候補日はその期間の平日で、祝日は外す
- 「組み合わせを実行」ボタン
- 運営の人と部署の一覧は、あらかじめ設定で用意する

**最初の版での割り切り**
- お知らせは送らない。参加者は自分でアプリを開いて確認する
- オンラインのランチは Meet の URL を付けない。メンバーどうしで用意する
- キャンセルはできない。出られなくなったらメンバーに直接連絡する

## 5. 1回の流れ
1. **受付開始**：開催期間の前の週に、対象者全員へ「候補日を選んでください」メール
2. **回答**：形式（対面／オンライン）と候補日（複数）を選ぶ。または「今回は休む」。締切までは何度でも直せる（休むから参加に戻すこともできる）
3. **締切前リマインド**：未回答の人にだけ締切前日にメール
4. **組み合わせ（締切後すぐ自動）**：6章のルールで組む
5. **通知**：組めた人にはメンバーと日時、カレンダー招待。組めなかった人には「次回は優先して組みます」
6. **前日リマインド**：メール
7. **当日ランチ**
8. **ランチ後の質問（翌日）**：「参加しましたか」と、相手ごとに「今後気軽に話せそう？ はい／いいえ」

※ 候補日を選ばなかった人は、その回は不参加として扱う（自動参加でも、日程が分からない人は組まない）。

## 6. 組み合わせのルール
**必ず守る**
- 1グループ3〜4人
- 新入社員を1人以上、迎える側を1人以上含める（目安：新入社員2人＋迎える側1〜2人）
- グループ内の全員が別の部署
- 全員が同じ形式（対面どうし／オンラインどうし）
- 全員が選んだ候補日に共通の日がある
- 本人が「組みたくない人」に登録した相手とは組まない（どちらか一方が登録していれば組まない）

**できるだけ守る（優先順）**
1. 前回組めなかった人を優先して入れる
2. 一度組んだ人とは組まない（どうしても組めないときだけ再会を許す）
3. 新入社員を多めに入れる（迎える側があまるより、新入社員があまらないほうを優先）

**組めなかった人**
- その回は見送り、本人にメールで知らせる
- 次の回で優先して組む

## 7. キャンセル
- 参加者は当日までアプリからキャンセルできる。残りのメンバーにメールで知らせる
- 残りが2人以上：そのまま実施できる。残りのメンバーは「このまま実施／中止」を選べる（1人でも中止を選んだら中止）
- 残りが1人：自動で中止。残った人は次回優先
- 代わりの人の補充はしない
- 無断欠席は「参加しましたか」で「いいえ」の扱い。罰則は設けない

## 8. 画面
### 画面の方針
画面案（案A ステップ型・案B 1画面まとめ型・案C カレンダー型）を見比べて決めた。

- **案A のステップ型をもとにする**：1画面に1つの質問にして、順に進める。初めての新入社員が迷わないようにするため
- **ホームと候補日を選ぶ画面は、案C のカレンダーにする**：自分の予定と見比べながら日を選べるようにするため
- **主に使う端末はスマホ**。スマホに合わせて作り、PC でも崩れずに使えればよい
- **祝日は候補日から外す**：カレンダーには表示するが、選べないようにする
- **回答は締切まで直せる**
- **部署は一覧から選ぶ**：自由入力にしない。表記の揺れで「別の部署」の判定がずれるのを防ぐため

### 参加者
| 画面 | 内容 |
|---|---|
| 初回登録 | 名前・メールは Google から取得。部署（一覧から選ぶ）、入社日、勤務形態（主に出社／主にリモート／半々）、迎える側として参加するか、を入力。入社日から「新入社員」か「迎える側」かを表示する |
| ホーム | 今回の回の期間をカレンダーで表示する。回答の状態（未回答／回答済み／今回はお休み／組み合わせ決定／組めなかった）と、選んだ日を出す。「候補日を選ぶ」（回答済みなら「回答を直す」）と「今回は休む」。組み合わせが決まったら、ランチの日をカレンダー上に示し、ランチの詳細へ進める |
| 回答 | 1. 形式（対面／オンライン）を選ぶ → 2. 候補日をカレンダーで選ぶ（いくつでも。祝日は選べない）→ 完了。締切までは、前の回答が入った状態から直せる |
| ランチの詳細 | メンバーの名前・部署、日時、形式、Meet の URL（オンライン時）、キャンセルボタン |
| ランチ後の質問 | 「参加しましたか」、相手ごとに「気軽に話せそう？」 |
| 自分の記録 | これまで会った人の一覧と、「話せそう」と答えた配属先以外の人数（成功基準1の自分の進み具合） |
| 設定 | プロフィール編集（異動時など）、自動参加の停止／再開、組みたくない人の登録 |

「組みたくない人」は理由の入力なし。相手にも運営にも見えない。

### 運営
| 画面 | 内容 |
|---|---|
| 開催設定 | 開催期間、受付開始日、締切日、候補にする曜日。祝日は候補日から外す |
| 集計 | 成功基準の全体集計（下記）。個人は特定できない形でだけ表示 |
| 参加記録の出力 | 回ごとの参加記録（名前・日付・形式・参加有無）を CSV で出力。経費精算に使う |

## 9. 成功の測り方
- **基準1**：ランチ後の質問で「気軽に話せそう？」に「はい」と答えた、配属先以外の相手の人数を本人ごとに数える。運営には「入社3ヶ月時点で3人以上の人の割合」だけを見せる
- **基準2**：勤務形態（主に出社／主にリモート／半々）ごとの参加率（対象者のうち、その回に実際にランチした人の割合）を並べて見せる
- 個々の回答（誰が誰にどう答えたか）は運営にも見せない。答えは相手にも見せない

## 10. お知らせ（メール）一覧
| タイミング | 宛先 | 内容 |
|---|---|---|
| 受付開始 | 対象者全員 | 候補日を選ぶ依頼 |
| 締切前日 | 未回答の人 | リマインド |
| 組み合わせ決定 | 組めた人 | メンバー・日時。カレンダー招待（オンラインは Meet 付き） |
| 組み合わせ決定 | 組めなかった人 | 見送りと次回優先の案内 |
| 前日 | 参加者 | リマインド |
| キャンセル発生 | 残りのメンバー | 誰が欠席か、実施／中止の選択 |
| ランチ翌日 | 参加者 | ランチ後の質問 |
| 入社半年 | 該当者 | 迎える側への切り替えの案内 |

## 11. 今後の検討事項・リスク
- **個人のフォローができない**：運営は集計しか見られないため、「3ヶ月で話せる人が少ない新入社員」に個別に声をかけられない。代わりに本人の「自分の記録」画面で進み具合を見せる。足りなければ、本人が同意した場合だけ運営に知らせる仕組みを検討
- **オンライン希望者が少ない回**：形式の振り替えはしないため、オンラインの人が続けて組めない恐れがある。次回優先で足りるか、参加率（基準2）を見て判断する
- **社員情報が本人入力**：部署や入社日の誤り・異動後の未更新で「別部署」「入社半年以内」の判定がずれる。異動の多い時期にプロフィール確認のメールを送るか検討
- **迎える側の回数上限なし**：補助の予算超過や、同じ人ばかりが迎える側になる偏りが起きうる。運用して偏りが出たら上限を検討
- **日によって出社とリモートが変わる人**：形式は回ごとに1つしか選べない。候補日ごとに形式を選べるようにするかは要検討
- **運営の確認なしの自動通知**：問題のある組み合わせを事前に直せない。「組みたくない人」の登録で防ぐ前提
- **オンラインの昼休み**：時間は 12:00〜13:00 を基本とする想定（要確認）
- **祝日のデータ**：どこから祝日を得るか（運営が登録する／祝日の一覧を使う）は未定。会社独自の休み（夏季休暇など）も外すかは要確認
- **部署の一覧の管理**：組織変更のときに、誰が一覧を直すかを決める必要がある。最初の版では設定で用意する
